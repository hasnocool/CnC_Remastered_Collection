# CnCTDRAMapEditor/Steamworks.NET/autogen/

## Responsibility
The machine-generated half of the vendored Steamworks.NET binding (Riley Labrecque, MIT header © 2013–2019): `#if !DISABLESTEAMWORKS`-guarded C# mirrors of the Steamworks SDK's `steam_api.h` / `steam_api_flat.h` surface. Every file is marked "This file is automatically generated — changes will be reverted when you update Steamworks.NET"; per repo policy it is vendored and not restyled.

## Design
Five generated files covering the whole API, each a mechanical translation of the SDK headers:
- `NativeMethods.cs` (~236 KB) — the `[DllImport("steam_api64.dll")]` flat entry points (`SteamAPI_Init`, `SteamAPI_RunCallbacks`, `SteamAPI_ISteamUGC_CreateItem`, …), one per exported function across all interfaces.
- `isteam*.cs` (32 files, `isteamapplist` … `isteamuserstats`) — per-interface wrapper classes mirroring `ISteam*` C++ interfaces; methods delegate to their `NativeMethods` counter
parts, user and gameserver variants side by side.
- `SteamCallbacks.cs` (~125 KB) — every callback struct (`UGCQuerySubmitted_t`, `ItemInstalled_t`, `HTTPRequestCompleted_t`, …) with matching sizes used by `CallbackDispatcher` registration.
- `SteamEnums.cs` (~98 KB) — all `E*` enums (`EItemState`, `EWorkshopFileType`, `ERemoteStoragePublishedFileVisibility`, …) with `[Flags]` where the SDK flags are.
- `SteamStructs.cs` + `SteamConstants.cs` — SDK POD structs and `k_*` constants (version strings, limits).

## Flow
Runtime path: `CallbackDispatcher` builds its type table from `SteamCallbacks.cs` structs → Steam client fires native callbacks → `NativeMethods` flat functions marshal them → dispatcher routes to managed delegates; interface classes are obtained via `SteamClient`-style accessors in `Steam.cs` and never constructed by editor code.

## Integration
Called from `Steamworkss.NET`'s hand-written facade (`Steam.cs`, `CallbackDispatcher.cs`, `InteropHelp.cs`, `Packsize.cs`) at the repo root of this folder, which in turn backs `Utility/SteamworksUGC`. Regenerates wholesale when Steamworks.NET is updated — treat as opaque; no editor types may leak into these files (they only touch `System`, `System.Runtime.InteropServices`, and the `Steamworks` namespace).
